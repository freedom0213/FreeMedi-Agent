# FreeMedi-Agent 前端布局方案 v1

> 阶段：患者端首版已实现；普通挂号和我的预约页面等待对应后端 API。
>
> 视觉基调：已确认 A+B。使用 Codex 式克制、清楚的视觉语气，并用清晰状态层级表达业务和 Agent 过程。

## 1. 设计目标

让第一次进入系统的人先认出这是医院就诊服务平台，再看到智能导诊 Agent 如何帮助完成预约。首页不以聊天框为主；Agent 页面则把对话、预约方案和执行状态组合成一个业务流程。

首版以患者端为核心。管理端作为后续精简工作台规划，不作为患者预约闭环的前置条件。

## 2. 患者端页面

### 首页：医院就诊服务门户

桌面端使用单一主导航和宽内容区，不采用后台式左侧任务导航。

1. **顶栏**：FreeMedi-Agent 品牌、首页、智能导诊、预约挂号、我的预约；右侧显示演示环境标识与当前演示用户。
2. **就诊服务入口**：主标题说明可办理的就诊服务；搜索框同时支持搜索科室/医生和输入就诊需求，默认动作是查询服务。
3. **智能导诊入口**：位于搜索区旁边的独立服务区域，用一句话说明能力和预约确认边界，按钮进入 Agent 流程。它不是铺满首屏的大聊天框。
4. **科室快捷入口**：以紧凑行列展示常见科室和“全部科室”，点击进入普通挂号路径。
5. **就诊信息**：展示预约规则、门诊时间和模拟数据说明，不使用虚构的医院规模、满意度或运营指标。

页面首屏应同时露出搜索/预约入口、智能导诊入口和科室入口。避免把统计数字或 Agent 技术能力当作首页主内容。

### 智能导诊与预约

桌面端采用主流程 + 进度侧栏的两栏布局：

- **主流程区（弹性主栏）**：顶部固定需求摘要，允许回看或修改科室、日期、时段、医生偏好和缺失项；下方依次展示用户需求、Agent 的必要追问、号源候选列表和确认摘要。候选方案用可比较的列表，不把每条都包装成装饰卡片。
- **执行状态侧栏（约 240px）**：显示理解需求、调用只读工具、形成方案、等待确认、写入后核验等事件；工具输入输出只显示面向演示的摘要。

窄屏改为单列顺序：需求摘要折叠在顶部，候选方案和确认区紧跟对话，执行记录放在可展开的“处理进度”区域。确认预约是唯一明确的主要写操作，并展示完整医生、科室、日期和时间。

### 普通预约挂号

普通预约不应被 Agent 流程取代。按科室、医生、日期、时段逐步筛选，结果以可比较的医生/号源行呈现；确认预约前展示完整方案。首版只承诺已有后端能力支持的查询与创建流程。

### 我的预约

用列表呈现预约日期、科室、医生和状态；点击一行查看详情。取消、改期只有在后端流程和规则实现后才加入界面。

## 3. 管理端布局（后续阶段）

管理端采用克制的左侧导航 + 主工作区，服务于工作人员查看和处理模拟数据：

- 预约记录：搜索、状态筛选、分页和预约详情。
- Agent 运行记录：任务状态、工具调用摘要、耗时、失败原因和事件回放入口。
- 演示数据说明：解释数据为合成数据，不代表真实医院。

首版管理端不扩展成完整 HIS 后台，不先做用户权限中心、复杂排班编辑、知识库运营或模型配置面板。当前后端未提供管理查询 API，管理端布局是后续方案，不意味着这些接口已经存在。

## 4. 交互状态

- **搜索/查询**：输入校验、加载状态、无匹配科室/医生、无可用号源。
- **Agent 追问**：明确显示缺少的条件；用户回答后更新顶部需求摘要。
- **候选号源**：显示可选状态和关键比较字段，不允许模型静默更换用户选中的方案。
- **预约确认**：写操作前呈现确认摘要；确认中防止重复提交；号源失效时返回重新查询并要求用户重新选择。
- **预约结果**：仅在后端核验成功后显示成功；失败或待核验需明确说明状态。
- **SSE 中断/刷新**：根据持久化事件恢复状态，给出重新连接或刷新后的可理解反馈。
- **空状态和错误**：说明当前没有记录/号源或发生了什么，以及用户下一步能做什么。

## 5. 视觉与响应式约束

- 延续 A+B：中性背景、少量蓝绿强调、克制的分隔线与圆角、稳定的文字层次。
- 医疗业务色承担真实语义，例如预约成功、待确认、失败；色彩同时配合文字标签。
- 首页使用门户式顶部导航；管理端使用侧栏。不要把两种导航混用到一个页面。
- 桌面端充分利用横向空间；移动端取消三栏并纵向重排，不产生横向滚动。
- 首屏优先放就诊动作与业务信息，Agent 轨迹属于解释和审计信息。

## 6. 实施边界与顺序

1. 先实现患者端首页、智能导诊预约、普通预约入口、我的预约基础视图。
2. 连接现有任务创建、发送消息、确认预约、任务状态和 SSE 事件 API。
3. 验收缺失信息追问、候选方案、确认、预约核验、断线恢复和错误状态。
4. 再依据实际需要补充管理查询 API 和精简管理端。

## 7. 非目标

- 不把首页做成通用 AI 聊天页或 Codex 式新建任务页。
- 不把 Agent 执行轨迹当作患者必须阅读的技术日志。
- 不加入诊断、处方、个体化用药建议或真实 HIS 对接。
- 不在管理 API 尚未实现时用前端假数据伪装管理端已可用。
