# FreeMedi-Agent 患者端前端改版讨论稿

**状态**　2026-11-19 · 方案讨论中

本稿根据《前端计划书》和三张参考图，结合现有 Vue 页面、预约接口和 [S6 验收记录](../product/s6-local-acceptance.md) 编写。面向求职展示所用的本地演示系统。主体设计覆盖首页、科室目录、智能导诊、预约挂号和我的预约，就诊准备、登录和全局导航随同统一样式。

## 1. 整体方向

首页帮助患者选入口。知道要看哪个科室的人可以直接挂号，需要帮助的人可以把需求交给导诊助手。导诊页帮助患者从追问走到选号、确认和结果核验。预约成功后，从同一条预约进入就诊准备，继续查看带来源的资料。

视觉沿用此前偏好的轻量风格，以计划书里的医疗绿为主要操作色。深青绿用于主按钮和选中状态，白色与浅灰绿用于页面和阅读区，浅蓝给医院资料与引用，淡紫少量用于区分 AI 追问或建议。普通文字用深灰绿。状态同时提供文字和图标，避免仅靠颜色区分。卡片用于表达可选对象、有明确边界的任务或结果，普通说明用标题和留白分组。

## 3. 各页设计

### 首页

**首屏。** 左边用一句贴近患者任务的标题，例如「找到科室，约好就诊时间」。紧接一个标明会进入智能导诊的输入框，按钮写「开始智能导诊」，下面保留「已知道科室？直接挂号」。右边用一张医患交流场景插画衬托信息层级。窄屏先展示标题和操作，插画移到操作区之后并缩小，第一屏优先保住入口。

首页目前会把输入内容传给导诊页，导诊页清除参数后发送。交互稿应明确按钮会提交这句描述。现有传递方式会让内容短暂出现在 URL 中，未登录时还会经登录跳转携带。后续需要单独决定是否改为一次性草稿交接；检查首屏表述和入口布局时可以先沿用当前行为。

**第二屏。** 先放少量科室卡和「全部科室」，再放一块导诊示例，用「描述需求 → 比较号源 → 核对预约」展示助手能完成的任务。第二屏的导诊区用示例讲清能力。医生推荐可后置，等能说清候选来源和排序依据后再考虑。服务说明和页脚交代合成数据、预约确认及导诊服务范围。

### 科室目录

两种落点都能复用现有接口。把完整网格放在普通挂号第一段，路径更短，也省去新路由，但用户需要先登录才能浏览这个页面。独立的只读科室目录多一个页面，可以从首页直接查看全部科室，且能让首页保留少量科室入口。**建议采用独立目录。** 从首页「全部科室」进入，沿用现有科室查询接口，点击卡片后进入 `/booking?departmentId=…`，由现有登录守卫处理身份检查和回跳。

目录顶部放科室名筛选，结果使用同一套图标网格；没有匹配时引导清除筛选。只有接口返回了描述才显示描述。卡片跳到当前科室的挂号流程，科室详情页可等有明确的资料浏览需求再做。首版导航保留已有四项，目录从首页进入。

### 智能导诊

全局导航在上方。桌面中间主栏最宽，示意比例约 60%，左右栏根据内容留出空间。左栏负责会话入口，右栏标题用「本次导诊」或「预约进度」这类患者能理解的中文。中等宽度先把会话栏折叠，手机按一列阅读，会话与本次导诊摘要由页头入口打开；选号和确认保留在主栏。输入框保持容易找到，在小屏键盘弹出时也要能看到当前编辑内容。

| 状态 | 左侧会话栏 | 中间主栏 | 右侧「本次导诊」 |
| --- | --- | --- | --- |
| 刚进入 | 「新建会话」、当前会话或其空态 | 「想看哪个科室，或哪里不舒服？」短提示、输入框、少量示例 | 一句任务提示，待患者提供信息后再显示摘要 |
| 收集需求 | 保持当前会话的选中状态 | 上一轮回复、需要补充的问题、可点击的短选项。快捷项复用现有回复入口，文案明确是否会直接发送 | 患者已提供的要点、已确定的科室或时间偏好。信息缺失时显示「待补充」，或隐藏未出现的字段 |
| 查到号 | 保持在当前会话 | 这轮结果上方放一行查询条件与「修改条件」；下方对比真实候选的医生、科室、日期、时段和差异，主动作「选择此号源」 | 展示「已查到号源，待选择」和稳定的需求摘要 |
| 等待确认 | 保持在当前会话 | 确认单显示刚选中的科室、医生、具体日期和时间。「确认预约」为唯一主动作，「返回换时间」回到本轮候选 | 显示「待你确认」和进度，核对以主栏确认单为准 |
| 核验中或完成 | 当前会话保持可识别 | 结果不确定时展示「核验原预约」，满足原重试条件才显示「重试原提交」；核验成功后展示结果和「查看原预约」 | 显示核验状态或完成状态，展开后可看必要的办理记录 |

- **条件有一个编辑入口。** 主栏候选上方的「修改条件」打开既有的科室、医生、日期和时段表单。右栏可显示足够短的当前需求作为回顾。通过对话或表单更新条件，都读取同一份任务状态。旧确认单应随既有状态失效，患者重新选号后才得到新确认单。
- **对话中的卡片做操作，右栏做回顾。** 科室建议、候选号源、确认单和预约结果排在对应的任务步骤里。资料答复附可展开的引用。右栏可显示患者自己提供的描述和已有科室建议理由，文案标明「你提供的信息」或「助手建议」。若结构化症状摘要当前无可用字段，首版显示有明确来源的患者原话或收起该区。疾病概率、AI 置信度和模型推理面板超出当前业务和数据范围。
- **每次错误只强调一个恢复动作。** 没查到号优先「修改条件」，号源被占优先「按原需求重新查号」，提交结果不确定优先「核验原预约」。资料不足和资料库不可用分别提示。患者能从提示和按钮看出接下来需要做什么。

#### 左栏历史会话的范围

| 方案 | 能力与代价 |
| --- | --- |
| 首版左栏显示新建、当前任务／空态 | 沿用现有按患者恢复当前任务的能力。可以先验证三栏空间和阅读顺序，真实历史列表留给后续 |
| 当前浏览器的最近会话 | 未来可只记录按患者隔离的任务索引，再经现有单任务接口读取。无法列出未被索引的任务或跨浏览器读取，还需处理退出、失效任务和切换时的待核验状态 |
| 账号级历史与会话管理 | 当前有按 ID 读任务的接口，缺少按当前患者列出任务的接口。要设计列表范围、时序、摘要、归属校验和管理操作，并补两账号隔离验收。改名、归档、删除各自需要明确业务语义 |

**建议先做第一种。** 左栏当前只有一个任务时保持轻量并可折叠，真实历史会话按独立功能评审。核验尚未结束时，保持现有新建限制。等能安全恢复旧任务后，再上线历史切换。

### 预约挂号

建议使用「选科室 → 看医生与时间 → 核对预约」三段。第一段复用科室网格。从首页或目录带入科室后，直接看到已选科室，以及可修改的入口。第二段把医生、日期、时段作为共同筛选条件，紧接着列出号源。「不限医生」「不限日期」沿用现有含义，患者选一个科室就能按现有逻辑查近期号源。日期筛选旁展示已有的查询截止日，只有查询返回的具体时段才标为可预约。

医生卡突出姓名、职称、擅长领域，缺少头像时用统一图标。结果可按日期分组，单条优先让时间、医生和选中状态容易辨认。严格按现有筛选条件查询，无号时展示可修改的条件。第三段复用导诊确认单的显示顺序；桌面可在结果旁显示，窄屏放在选中号源之后。确认、原单核验、相同提交重试、冲突后刷新沿用各自的现有状态。

### 我的预约与就诊准备

默认让最近一次待就诊的记录更醒目，卡片先读时间，再读科室、医生和预约状态。可用现有日期、状态做前端展示排序，已过就诊日的记录以历史记录呈现，保留原预约状态。用户从「查看原预约」带编号进入时，优先定位指定记录。详情显示预约编号和预约来源；「就诊准备」沿用现有入口，继续使用关联的预约信息及医院资料引用。

如果当前没有记录，提供「去预约挂号」；如果记录加载失败，显示重试；如果指定预约不能读取，明确告知这条记录不可用。页面呈现以现有接口返回为准，取消、改期和支付可作为后续功能讨论。

### 共用导航及反馈

顶栏让 Logo 与主导航按一组水平排版，用较短间距消除断层，患者登录或账号操作对齐右侧。窄屏把导航收进同一菜单。页面共用主次按钮、科室图标、号源行、确认单和状态反馈的视觉规则。就诊准备沿用来源组件；登录沿用现有身份检查与回跳。候选、卡片和确认控件能用键盘操作，选中和禁用都有可识别状态。

## 4. 建议执行顺序

1. **先定导诊三栏线框和关键状态。** 用「刚进入」「查到号」「等待确认」检验左栏权重、条件与候选的距离，以及确认单的焦点。附一个窄屏状态，验证两侧栏收起后仍能正常完成主流程。
2. **把共用交互样式落到导诊。** 从顶部导航、主次按钮、号源卡、确认单、加载和恢复提示入手。在现有页面上逐段调整，以 S6 业务流程作为回归基线。
3. **再把共用模式接到自助挂号、我的预约和就诊准备。** 检查两条路径在选号、确认和定位原预约上的一致性，同时保留自助查询的严格筛选语义。
4. **完善首页和科室目录。** 确定首页插画与目录图标，在入口处接通两条路径，再用统一样式收尾登录页和全局导航。

## 5. 改版后验收

| 场景 | 通过标准 |
| --- | --- |
| 首页进入两条路径 | 一句话能进入导诊；选科室能进入对应的普通挂号；登录回跳保留原入口及科室选择 |
| 导诊三种状态 | 初次进入能找到输入；查到号能看懂查询条件和各条候选差异；确认单与刚选的号一致 |
| 多轮修改 | 表单和对话都能改条件，旧确认单失效；返回候选后可换号，文本回复及选号阶段预约数不增加 |
| 失败恢复 | 号源冲突后保留条件并允许重新选号；回包丢失先核验，同一提交重试只返回原预约 |
| 预约后路径 | 两种方式预约成功后都能定位原记录，从该记录进入就诊准备并展开资料来源；资料无结果和不可用均有清楚反馈 |
| 本人数据和窄屏 | 两位患者只读到各自的预约；桌面和窄屏都看得到动作、时间和状态，键盘焦点可见且不会被底部输入区遮挡 |

## 6. 建议优先确认

1. **科室目录首版是否作为独立页面。** 建议独立目录，复用现有读取接口，首页露出快捷科室和「全部科室」。
2. **账号级历史是否随视觉改版一起交付。** 建议先确定三栏空间和中栏任务操作，左栏首版保留当前任务；如要同步交付跨浏览器历史，再单独确认接口范围和身份隔离方案。
