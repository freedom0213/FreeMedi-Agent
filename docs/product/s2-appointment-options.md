# S2 预约需求、候选与确认

页面和对话现在更新同一个患者任务。患者可以直接选科室、医生、日期和时段，或在对话中补充条件。只提交本轮变化的字段，其他字段沿用已保存值。任务为每个已填写条件记录最后一次有效修改的来源。

## 数据与交互

- 使用既有 `agent_task.collected_facts` JSON 保存 `requirements` 和当前 `candidateBatch`。候选从与普通挂号共用的 MySQL 查询得到，最多三条。查询和选择都不占号。
- 指定日期和时段时先做严格查询。无匹配时，仅放宽获授权的日期或时段并逐项标出差异。科室、医生保持原条件。找不到目录实体会单独提示。
- 点击候选时校验患者、查询批次、候选成员关系及号源当前可用性。成功后生成确认方案。重选另一候选时，旧方案失效和新版本写入一起提交。
- 只读回复保留确认单。保存实际条件变化时，旧方案失效。预约仍通过独立确认请求写入并核验。刷新后由任务快照恢复条件、候选和已选方案。

| 接口 | 影响 |
|---|---|
| `POST /api/v1/tasks/{taskId}/requirements` | 更新页面提交的部分条件并查询。接受 `departmentId`、`doctorId`、`appointmentDate`、`clinicPeriod`、`dateFlexible`、`periodFlexible`。省略表示沿用，日期和时段用空串清除，目录选项用 null 清除。 |
| `POST /api/v1/tasks/{taskId}/selection` | 提交 `batchId` 和 `slotId`，由服务端生成确认方案。 |
| 现有消息、任务快照和确认接口 | 路径与请求结构保留。对话查到候选先返回 `PROPOSAL_READY`，选择后才进入 `AWAITING_CONFIRMATION`。调用方可从 `task.facts` 读取条件和候选。已生成的旧确认单仍以原方案版本和有效期处理。 |

这两个新接口沿用 S1 的服务端会话、CSRF 和任务归属检查。数据库表结构与 Flyway 迁移保持原样。

## 本地验收

2026-11-18 在隔离 MySQL 8.0.34 上执行 130 项回归，含 53 项 MySQL 集成。失败、错误和跳过均为 0。Vue 类型检查、Vite 生产构建和后端打包通过。

| 验收 | 证据 |
| --- | --- |
| A01 直接与补问 | REST 验证点名陈医生可直接查号，未知科室单独提示。流式回归验证只描述头疼并询问科室时获得就诊方向；冒烟脚本还验证症状、中文日期与最近号源。 |
| A02 共同调整 | Chrome 用页面填科室、医生、日期和上午，随后用对话把时段改成下午。页面和快照都更新为下午，医生及日期保留。 |
| A03 候选与选择 | 浏览器显示两个实际候选，选择第二条后才出现确认单。集成测试验证最多三条，查询无确认方案、未占号，拒绝陈旧批次和任意号源 ID，换选另一条会更新方案版本。 |
| A04 条件与偏好 | 浏览器严格晚间查询返回零，明确允许其他时段后标注“时段不同”。独立 HTTP 验证无号日期的“必须”和“优先”行为，以及“必须周六”的解析。 |
| A05 咨询与修改 | 浏览器咨询就诊材料时原方案不变；实际修改后原确认方案被拒绝。回归还验证聊天中的“好的”不会提交预约。 |
| A15 与刷新 | 两患者的真实会话不能互相更新需求或选择号源。重新加载页面保留需求和候选，明确确认后“我的预约”与隔离数据库中唯一写入的预约一致。 |

浏览器使用实际 Vite、Spring Boot 和 MySQL，模型为本地确定性实现。DeepSeek 的自然语言泛化和只读咨询的资料引用分别留给真实模型与 S3 验收。日志、截图及浏览器探针在本机 Git 忽略的 `target/s2-verification/`。
