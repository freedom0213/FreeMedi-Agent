# 管理端 Agent 工具与模型配置

登录管理端后，从左侧进入「工具调用日志」，或打开 `/admin/tool-logs`。页面按最近更新时间展示 24 个任务，也可输入完整任务编号定位更早的任务。调用记录按 S5 的事件序号排列，每页 50 条。

「统计与观测 → Agent 执行时间线」（`/admin/agent-timeline`）复用同一份任务追踪记录，按轮次分组、按事件序号展示模型判断、工具调用、预约确认、创建与核验。可按步骤类型筛选当前已加载的记录，继续加载后续记录。工具调用日志与时间线可携带当前任务编号互相跳转，刷新链接仍定位同一任务。

每条记录显示轮次、步骤、动作或工具名称、处理结果与耗时。失败时显示原因码，同一个调用的第 2 次及之后的尝试标为重试。预约确认、写入和核验分别展示。已计时的动作显示毫秒，其他步骤显示「—」。从 S5 之前创建且没有追踪记录的任务进入时显示空状态。

## 接口

| 管理员只读接口 | 返回内容 |
| --- | --- |
| `GET /api/v1/admin/agent/tasks` | 最近任务的编号、类型、状态、轮次及更新时间。 |
| `GET /api/v1/admin/agent/tasks/{taskId}/trace?after=0` | 任务摘要、当前页的追踪动作及下一页游标。 |

两个接口沿用管理端角色校验，读取现有任务表和 S5 的事件记录。响应只包含排查调用链所需的摘要。患者消息、模型请求、工具原始入参与返回体不出现在管理端接口中。

## 浏览器验收

Chrome 连接实际 Spring Boot 和隔离 MySQL，从首页提交导诊需求，查到 3 个候选，选号并确认。患者端显示预约已创建并核验，数据库对应账号只有一笔预约。管理员按同一任务编号打开日志，看到模型判断失败（`MODEL_TRANSIENT`、153 ms）、第 2 次模型判断成功（14 ms）、查号（14 ms）、创建预约（24 ms）和核验成功。现场耗时以页面记录为准。

验收使用本地模型替身，让第一次模型请求返回 HTTP 503，第二次正常返回查号指令。验收中确认 LangChain4j 会包装供应商 HTTP 异常，适配器现已识别内层状态码并复用原有限重试策略。截图和验收结果保存在本机 `target/admin-tool-logs/`。

## 就诊运营看板

在「统计与观测 → 就诊运营看板」（`/admin/visit-operations`）按出诊日期查看每日预约趋势，以及科室、医生的预约和号源明细。默认展示医院当地日期起的 14 天，支持选择最多 90 天的区间并按科室筛选。

有效预约按当前 `BOOKED` 状态统计，其中 `PORTAL` 对应普通挂号，`AGENT` 对应智能导诊。可预约余号采用患者端开放、未开始且可查询的号源口径，已占用号源按 `RESERVED` 状态统计。每日趋势和明细可跳到对应排班，带上日期、科室或医生筛选。

`GET /api/v1/admin/observability/appointments` 接受 `from`、`to` 与可选的 `departmentId`，返回汇总、每日渠道统计和明细。接口只返回汇总数据与科室、医生信息。

## AI 调用观测

在「统计与观测 → AI 调用观测」（`/admin/model-calls`）查看尝试数、失败率、重试、平均耗时、P95、每日趋势、失败原因和模型版本。默认查询截至今天的 7 天，支持按北京时间的事件记录日期查询最多 31 天。明细可以按结果筛选，点击任务编号打开执行时间线。

每条 `MODEL_DECISION` 事件计一次尝试。失败后重试并成功会计两次尝试、一次失败和一次重试。P95 使用至少覆盖 95% 的最小已记录耗时，平均耗时及 P95 均忽略没有计时的历史记录。启动配置沿用事件里的运行模式，管理端配置按实际使用的版本归组。

管理员只读接口为 `GET /api/v1/admin/observability/model-calls` 和 `GET /api/v1/admin/observability/model-calls/attempts`。明细按记录时间和事件 ID 反向分页，每页最多 50 条。统计范围为 Agent 模型判断，供应商层的格式纠正次数、Token、费用、向量模型及配置连通性测试均在此口径之外。

## 工具注册表

管理员从左侧进入「工具注册表」，也可打开 `/admin/tool-registry`。展开工具可查看用途、模型参数的名称和类型、是否必填及字段说明。

| 工具 | 用途 | 模型参数 |
| --- | --- | --- |
| `findAvailableSlots` | 更新当前任务中本轮明确提供的条件并查询号源 | 科室、医生、日期、时段、是否允许放宽日期或时段、返回数量，共九个可选字段 |
| `getAppointmentRules` | 读取预约系统的技术限制 | 无参数 |
| `searchHospitalKnowledge` | 检索已发布的院内资料并返回可核对的来源 | `query` 为必填字符串 |

`GET /api/v1/admin/agent/tools` 从运行时读取注册定义，需要管理员会话。DeepSeek 适配器也从同一份 `ReadToolSpec` 生成工具参数。患者点击预约确认单上的「确认预约」后，后端才会创建并核验预约。

管理员可启用、停用内置工具，并为单个工具设置超时或恢复继承默认值。变更从下一次 Agent 请求开始生效。关掉查号会同时暂停 Agent 对话和表单查号，普通挂号独立运行。关掉资料检索会暂停导诊问答与预约后就诊准备的资料查询。已生成且仍有效的确认单仍可由患者确认。工具定义和参数由后端代码维护。

Chrome 连接实际 Spring Boot 和隔离 MySQL，从管理端菜单打开注册表，核对了三个工具的用途以及全部模型参数。另用独立患者会话确认接口返回 `403`。163 项隔离 MySQL 测试与 21 项浏览器回归通过。截图和结果保存在本机 `target/admin-tool-registry/`。

## AI 模型配置

管理员从左侧进入「AI 模型配置」，也可打开 `/admin/model-config`。页面展示当前导诊决策模型、单次模型调用超时、单次工具调用超时和整轮请求超时。启用本地演示规则时，模型栏显示演示模式。

「AI 能力配置 → Prompt 模板」只开放导诊沟通和选号确认引导。底稿由应用维护，编辑会保存独立版本。试跑使用当前聊天模型和合成用例，比较生效版与候选版，只展示回复和拟调用的工具。全部候选用例通过后可手动启用，下一轮请求采用新版本。通过当前配置试跑的历史版本可重新启用，也可直接恢复内置模板。Agent 执行时间线显示每次模型判断使用的模板版本。

`GET /api/v1/admin/agent/model-config` 需要管理员会话，显示生效版本、模型地址、测试结果和调用策略。API Key 仅在保存时输入，读取接口不返回密钥。

新增或编辑模型会保存新版本。测试使用合成输入，检查结构化回复与工具调用，成功后才可手动启用该版本。测试不执行工具，也不访问患者数据。启用后的下一轮请求采用新模型，已开始的请求继续使用原快照。历史中通过测试的版本可以重新启用，管理员也可以恢复启动配置。模型判断日志记录使用的版本。

部署时应用 Flyway V9。要在页面保存模型，需要在后端进程中配置 `MEDIFLOW_LLM_SETTINGS_KEY`，值为 32 个随机字节的 Base64 表示。重启时使用同一个密钥，以便读取已有配置。模型 API Key 以加密形式存入数据库。除已有启动地址外，其他兼容接口须通过 `MEDIFLOW_LLM_ALLOWED_BASE_URLS` 配置为逗号分隔的 HTTPS 基础地址，再从页面录入。知识库向量模型配置独立维护。

模型与工具设置保存在 MySQL。本功能面向单实例运行，服务启动时先加载已启用的数据库版本。没有启用数据库版本时，系统使用已有的环境配置或本地演示规则。

Agent 对列出的临时故障最多重试一次。DeepSeek 的格式纠正最多一次，用于重新生成不符合约定的输出。供应商 SDK 的自动重试为零。Agent 的单次调用时限也涵盖内部的格式纠正，整轮时限限制包括重试在内的总耗时。

浏览器连接实际 Spring Boot 和隔离 MySQL，将模型、工具和整轮超时分别设为 1.234、2.345 和 6.789 秒。管理员从菜单打开页面后，三个时间、模型名称和重试设置均与运行时接口吻合。以空密钥重启后，页面正确显示「本地演示规则」，接口响应与页面均未暴露测试密钥。此验收检查运行时配置的展示，未发出 DeepSeek 推理请求。164 项后端测试与 22 项浏览器回归通过。截图和响应保存在本机 `target/admin-model-config/`。
