# S4 预约关联的就诊准备

从「我的预约」选择一笔已预约记录，再进入「就诊准备」。普通挂号和智能导诊的预约都可使用。页面展示后端读取的本次预约科室、医生和时间，可询问到院准备、证件或取号并展开来源，也可回到同一笔预约详情。

## 实现与接口

复用现有 `agent_task.task_type` 和任务 JSON，保存独立的 `VISIT_CONSULTATION` 任务及创建时的 `visitAppointment` 快照。普通挂号也能创建咨询，无需先创建预约 Agent 任务。原预约记录及原 Agent 任务保留原状态，无新表或 Flyway 迁移。

`POST /api/v1/appointments/{appointmentNo}/consultation` 校验患者会话和 CSRF，通过患者与预约号查本人已预约记录。成功返回 `{ taskId }`，重复或同时打开同一笔预约复用一个任务。锁定预约行、查询或创建咨询、初始化会话和任务在同一数据库事务中完成。他人的预约返回 404。

既有任务快照由 `taskType` 区分咨询类型，消息仍走现有 REST/SSE 接口。咨询回答预约事实时使用后端快照，准备类问题调用 S3 的资料工具。服务器拒绝咨询任务的需求修改、候选选择和预约确认。咨询不会根据普通预约推断检查安排或给出禁食、停药指示。

## 验收

2026-11-18 在 Chrome、隔离 MySQL 8.0.34 和真实 Qdrant 1.13.6 上完成 A14 与新增入口的 A15 验证。

| 场景 | 结果 |
| --- | --- |
| 普通挂号与 Agent 预约 | 两种预约都能从详情进入咨询，展示实际预约信息。询问“这次去要带什么？”可展开医院资料。 |
| 返回与恢复 | 刷新使用同一咨询任务，能看到历史回复和来源。点击返回可定位到原预约。 |
| 只读与归属 | 直接调用需求修改、选号及确认返回 403。另一位患者无法开启对应预约的咨询，也无法读取任务或发送流式消息。咨询后预约数不变，原 Agent 任务保持 `COMPLETED`。 |
| 并发与资料范围 | 两个并发请求打开同一笔预约复用一个任务。询问是否需要自行停药时提示资料不足。 |

隔离 MySQL 回归 137 项通过，无失败、错误或跳过。Vue 类型检查、Vite 生产构建和后端打包通过。浏览器与测试证据位于本机 `target/s4-verification/`。S3 真实 DeepSeek 补试及资料版本验证见[S3 记录](s3-knowledge-consultation.md)。
