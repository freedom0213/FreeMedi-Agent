## 2. 实际采用的技术与边界

- **MySQL 是事实来源**：保存文档、版本、发布状态、片段原文与索引状态；Qdrant 只保存向量和过滤元信息，不保存正文或实时号源。
- **默认向量化**：本地 ONNX `bge-small-zh-v1.5-q`，512 维；模型随 Maven 依赖提供，运行时不需要额外下载或 API Key，首次使用初始化。API 实现可配置 SiliconFlow BGE-M3（1024 维），需要独立凭证。没有本项目对照数据可证明 API 方案一定更好。
- **默认索引**：`qdrant`；`memory` 仅用于测试/进程内验证，重启后丢失；`none` 明确表示索引不可用。配置见 [application.yml](../../src/main/resources/application.yml) 与 [KnowledgeConfiguration](../../src/main/java/com/mediflow/agent/config/KnowledgeConfiguration.java)。
- **Qdrant**：Compose 固定 `v1.13.6`，适配器直接使用 REST。Compose 当前只有此服务；MySQL 另行提供，Redis 业务能力未接入。不能把“无需向量化 API”说成真实检索不需要数据库服务。
- **集合按模型命名**：不同模型不能共用同一集合；更换模型须重建相应索引，不能只改配置后继续依赖旧 `INDEXED` 标记。
- **切块初始值**：目标 400 字符、重叠 80、上限 800；保留章节归属，标题只作元信息，段落被迫切开时才重叠。尚无完整评估证明这是最优参数。

## 3. 首批资料与存储

当前 [knowledge 目录](../../knowledge/) 只有 **6 篇合成样本**：预约规则、就诊须知、检查准备各一篇，心内科介绍一篇、医生介绍两篇。旧计划中的六篇科室/七篇医生是目标数量，不能列为已经完成。

V7 的实际约束见 [迁移](../../src/main/resources/db/migration/V7__knowledge_documents_and_chunks.sql) 和 [数据模型](../database/data-model-v1.md)：

- 文档唯一键是 `(doc_no, version)`，不是 `doc_no` 单列唯一。
- 片段唯一键是 `(document_id, version, chunk_no)`。
- 医生介绍要求 `doctor_id` 与 `department_id`；科室介绍要求 `department_id`；通用资料可不关联实体。
- `PENDING / INDEXED / FAILED` 是片段索引状态；文档表支持 `DRAFT / PUBLISHED / ARCHIVED`，但不代表已有三态管理界面。

S3 更新了合成预约规则，明确当前可操作范围，并从技术工具移除了旧的取消期限。新资料使用既有导入与索引脚本发布。

## 4. 当前真实导入与索引流程

```text
knowledge/**/*.md → 解析元信息与正文 → 比较内容哈希
  ├─ 未变化：跳过（不因重新导入复活已下架资料）
  └─ 新增/变化：事务内归档旧版本 → 直接插入 PUBLISHED 新版本 → 切块为 PENDING

待索引的发布片段 → heading + content → Embedding → Qdrant upsert → 标记 INDEXED
索引出错 → 标记 FAILED → 后续索引命令重试
```

需要避免的旧描述：

- 当前导入器**直接发布**受控文件，没有人工“草稿→审核→发布”流程或管理页面。审核发布曾是目标，尚未实现。
- 解析器拒绝未知元信息字段；这不等于已实现对正文中全部号源/库存内容的自动识别。资料内容仍需核对。
- 点 ID 是 MySQL `chunkId`，同片段重复 upsert 覆盖同一点；不是旧文档所写的文档/版本/位置哈希。
- 更新时旧版本在 MySQL 归档；索引虽有 `removeVersion` 能力，现有导入/增量索引路径没有自动调用它。旧点可能暂存，查询回读 MySQL 时拒绝未发布版本；完整重建可清理旧点。
- 重建先删除索引集合，再将当前发布片段重置为待索引。默认一次处理上限 500；更大资料集需检查待处理状态并继续运行，不能仅凭命令退出成功就宣称所有片段完成。
- 删除 Markdown 文件不会自动下架已经导入的 MySQL 资料。

## 5. 检索与 Agent 接入的真实边界

底层检索：问题向量化 → Qdrant 候选片段 ID → 回读 MySQL 同版本发布资料 → 返回标题、章节、正文、来源与分数。当前检索按 TopK 返回候选，没有可保证“相关/无关”的固定阈值。

历史探针记录中，无依据问题和有依据问题的分数区间重叠。因此 **返回片段不等于片段足以回答问题**，后续需验证回答是否受证据支持，不能仅依靠 `count > 0`。

工作区知识工具的签名为：

```text
searchHospitalKnowledge(query, docType?, departmentId?, doctorId?, topK?)
```

首批从受控资料中仅选择支持当前问题的章节，回复摘取原文并保存实际引用。检索失败与查无依据分别报告，均保留当前预约。医生目录查询同时检查所在科室状态；科室和医生介绍的患者端问答仍待覆盖。[S3 验收](s3-knowledge-consultation.md)

| 项目 | 当前证据或遗留 |
|---|---|
| 有依据时能定位来源并展开片段 | 就诊准备与预约规则已通过真实浏览器验收 |

## 7. 现有命令与历史验证

以下是本地复验入口。写入目标取决于数据库与索引配置，使用专用实例执行。

- 文本导入：[scripts/import-knowledge.ps1](../../scripts/import-knowledge.ps1)，需要 MySQL，不需要向量化 API 或 Qdrant。
- 增量索引：[scripts/index-knowledge.ps1](../../scripts/index-knowledge.ps1)；`-Rebuild` 删除当前模型集合并由 MySQL 重建，需要可达的 Qdrant。
- MySQL 自动化：[scripts/test-mysql.ps1](../../scripts/test-mysql.ps1)，使用隔离库；包含本地向量化与内存索引测试，不能说整个套件没有外部进程依赖。
- Qdrant 适配器：[scripts/test-qdrant.ps1](../../scripts/test-qdrant.ps1)，单独连接真实 Qdrant，不能用裸 Maven 跳过测试的结果冒充执行通过。
