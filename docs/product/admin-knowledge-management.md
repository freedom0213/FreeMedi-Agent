# 管理端院内资料与本地启动

管理员从 `/admin` 进入独立登录页。登录后默认打开工作台首页。侧栏将已交付页面归入「基础数据管理」「AI 能力配置」「医学知识库（RAG）」「Agent 工具中心」和「统计与观测」，并提供「退出系统」。原「院内资料」位于「医学知识库（RAG）→ 知识文档」，保留原链接。管理端采用 [RuoYi-Vue3 TypeScript](https://github.com/yangzongzhuan/RuoYi-Vue3/tree/typescript) 的侧栏、顶栏与内容区布局，接入本项目的 Vue 应用和 Spring Boot 会话。后端从现有 MySQL 用户表校验 `ADMIN` 角色。

## 在本机打开

沿用 [S6 本地启动配置](s6-local-acceptance.md#windows-本地启动)中的 MySQL 和 Vite。管理端从 MySQL 获取资料版本、片段和索引状态。仅验收管理端时可以用 `MEDIFLOW_KNOWLEDGE_INDEX=none` 启动。验收患者引用时启动 Qdrant 并索引演示资料。资料列表为空时，用 S6 的导入步骤准备演示资料。

在启动后端的 PowerShell 中设置管理员账号和密码。命令会提示输入密码，仓库不存放管理端默认凭据。

```powershell
mvn -DskipTests package
if ($LASTEXITCODE -ne 0) { throw '后端打包失败' }
$env:MEDIFLOW_ADMIN_USERNAME = 'local-admin'
$adminPasswordInput = Read-Host '设置本地管理员密码' -AsSecureString
try {
    $env:MEDIFLOW_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $adminPasswordInput).Password
    java -jar target/mediflow-agent-0.1.0-SNAPSHOT.jar '--spring.profiles.active=mysql'
} finally {
    Remove-Item Env:MEDIFLOW_ADMIN_PASSWORD -ErrorAction SilentlyContinue
    $adminPasswordInput.Dispose()
}
```

首次启动会在所选 MySQL 数据库中创建账号，只保存 BCrypt 密码哈希。重启会保留已有账号及密码，使用与患者重名的账号会提示配置冲突。后台和患者端使用独立会话，可在同一个浏览器里同时登录。后端重启后，两端分别重新登录即可。

前端保持 Vite 的默认开发端口时，打开 [本地管理端](http://127.0.0.1:5173/admin)。

## 基础数据管理

「科室管理」和「医生管理」支持列表筛选、新增、编辑和启停。科室编码与医生所属科室在创建时确定。启停会影响患者看到的可用号源，未来有效预约会阻止停用。

「排班管理」可以按科室、医生、日期和状态筛选，展开查看每个号源。新增时按北京时间填写未来日期、时段、开始时间、每号时长和数量，预览后一次生成排班与全部号源。管理端可排到今天之后第 90 天，患者普通挂号和智能导诊均按含当天的 28 天查号。有效预约或仍占用的号源会阻止关闭。没有占用时可以关闭排班及其可预约号源。普通挂号、Agent 确认和关闭操作通过数据库锁协调，避免同一排班既关闭又新增有效预约。

在排班行点「查看预约」可带着该排班的筛选条件进入「预约明细」。进入签到窗口后可以核对并为患者办理签到。「操作记录」支持查创建、取消、签到和改约结果，成功改约可从前后两个编号双向追溯。 [主分支干净环境验收](s6-local-acceptance.md#2026-11-26-主分支干净环境验收)

## 核对版本和片段

「医学知识库（RAG）」分为四个入口。医学知识库按已有资料类型汇总文档、版本和已发布片段的索引状态。知识文档继续管理导入、版本、发布和下架。知识片段支持跨文档筛选、查看正文，并定位到来源版本的具体段落。向量化与检索显示当前模型、维度、集合及向量核验结果，能用已发布版本进行语义试搜；结果分数表示向量相似度。

索引表将 MySQL 状态与当前集合的向量核验分开显示。可对已发布且待索引、索引失败或实际向量缺失的单个片段重试。草稿继续通过文档详情建索引和发布，归档资料不会参加试搜。当前向量模型也可在「AI 模型配置」查看。

| 页面 | 可验收的行为 |
| --- | --- |
| 工作台 | 查看项目用途，从入口进入院内资料。 |
| 资料列表 | 按标题或编号搜索。每份资料默认展示最新已发布版本，没有已发布版本时展示最新版本。分列显示发布状态、索引统计和患者引用资格。 |
| 版本详情 | 在下拉框切换历史版本。核对来源、发布时间和片段数。选择片段后查看顺序号、章节、正文、字符数、索引状态与引用资格。 |
| 失败与归档 | 已发布版本中的已索引片段可参与检索，待索引和索引失败片段暂不可引用。归档版本即使曾索引也不进入新问答。既有回答保留原引用记录。 |
| 下架确认 | 在当前发布版本的详情点「下架资料」。确认单展示资料名称和编号、发布版本和停止参与检索的片段数。确认后该版本归档，可以继续查看片段正文。 |
| 导入与发布 | 预览 UTF-8 Markdown，核对片段后保存草稿。索引完成再确认发布，详情保留新旧版本。 |

「可参与检索」展示片段的发布和索引资格。实际回答还会根据问题、检索结果和资料适用范围选择来源。管理页展示经归类的失败原因，原始技术错误仍在本地索引日志或资料维护命令里查阅。

## 下架接口与失败恢复

`POST /api/v1/admin/knowledge/documents/{docNo}/archive` 需要管理员会话和 CSRF 令牌，请求体为 `{"version": 2}`。后端在事务中锁定同编号的版本记录，仅归档确认单对应的当前发布版本。成功返回 `204`。该版本已归档且没有其他发布版本时，同版重试也返回 `204`。当前发布版本变化时返回 `409`，页面引导管理员查看当前版本并重新确认。请求结果不明确时，「核验下架结果」重新读取同一版本的状态。

下架保留资料、片段和历史回答的来源快照，也保留当前 Qdrant 向量。患者新问答对 Qdrant 命中再次核对 MySQL 发布状态，归档版本不会被引用。已有的索引重建命令只为仍在发布的资料生成向量。原有 [本地资料维护命令](s6-local-acceptance.md#本地资料维护)提供按编号下架全版本的操作。

## Markdown 导入预览

在「院内资料」点「导入预览」，选择文件后点「解析并预览」。可以用仓库中的 [门诊就诊须知](../../knowledge/visit-notice.md) 核对格式。文件上限为 256 KiB，头部使用两个 `---` 包住 `doc_no`、`title`、`type`、`source`。医生资料还需要 `department_id` 和 `doctor_id`，科室介绍需要 `department_id`。

页面显示资料信息和切分后的片段序号、章节、字符数、正文。同编号有新内容时，页面显示当前发布版本及预计版本。内容与已有版本相同则标记重复，可点开对应的历史版本。预计版本根据预览时读到的记录计算。

`POST /api/v1/admin/knowledge/import-preview` 需要管理员会话和 CSRF 令牌，使用 `Content-Type: text/markdown; charset=UTF-8` 发送文件内容。接口复用命令行导入的解析、内容哈希和切分规则，只查询资料版本与相关编号。预览不保存文件、创建版本、更新发布状态或生成向量。

## 新版发布

现有命令行导入在写入新版时归档旧版，随后另行建索引。它适合初始化演示资料或安排维护窗口。管理端需要在建索引期间继续提供旧版，因此采用「保存草稿 → 建立索引 → 确认发布」。

| 阶段 | 管理端操作 | 患者可引用的版本 |
| --- | --- | --- |
| 保存草稿 | 从预览保存，后端重新校验文件内容、最新版本和当前发布版本。相同草稿可继续办理，历史重复内容打开原版本。 | 原发布版。首次发布前暂无可引用版本。 |
| 建立索引 | 按草稿版本处理片段，展示已索引、待索引和失败数量。失败后在同一草稿上重试。 | 原发布版。草稿和归档版本在向量排序前排除。 |
| 确认发布 | 确认单列出将发布的新版本、将归档的旧版本和已索引片段数。确认时核对草稿的向量是否齐全、原发布版本是否仍与确认单一致。随后在同一 MySQL 事务中发布新版并归档旧版。 | 新问题使用新版。历史回答继续展示作答时的来源。 |

管理端复用现有文档、片段和状态字段。下列接口都需要管理员会话和 CSRF 令牌。

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/admin/knowledge/import-drafts` | 发送与预览相同的 Markdown，附上内容哈希、预览时的最新版本号和当前发布版本号。相同草稿的重复提交返回原版本。 |
| `POST /api/v1/admin/knowledge/documents/{docNo}/versions/{version}/index` | 每次处理一个片段。页面连续调用并显示进度，失败或关闭详情后可以回到原草稿继续。 |
| `POST /api/v1/admin/knowledge/documents/{docNo}/versions/{version}/publish` | 请求携带确认单里的 `expectedPublishedVersion`，首次发布填 0。发布成功返回 `204`。 |

发布仅针对最新草稿，成功时旧发布版和此前草稿归档。确认后如果另一位管理员先发布或下架，接口返回版本冲突，页面允许重新读取状态。发布回包丢失时，从同一版本详情核验，无需再次提交。草稿可以从「院内资料 → 继续草稿」或版本选择器找回。

患者检索先用 MySQL 当前允许检索的文档版本标识约束 Qdrant 候选，再沿用命中后的状态复核。草稿或残留的历史向量不会挤占可用候选。最终发布先核验 Qdrant 中的向量，再切换数据库状态。索引重建与发布在同一资料库内互斥，缺失的草稿向量会标回待索引。
