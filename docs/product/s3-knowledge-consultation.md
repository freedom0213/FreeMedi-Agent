# S3 就诊准备、预约规则与资料来源

本批交付智能导诊内的只读资料咨询。患者可以在等待确认时查资料，查询命中、查无依据或服务故障都保留已选预约方案。

后续已用真实模型补验医生和科室资料、状态查看及受控下架。当前操作见[S6 综合验收](s6-local-acceptance.md)。

## 实现与影响

- Agent 支持 `searchHospitalKnowledge`。本地演示模型可识别常见的资料问题，DeepSeek 适配器也声明了工具及查询参数。
- Qdrant 返回候选片段，MySQL 核对发布状态、版本和查询范围。首批只选与问题对应的已核对资料章节，最多三段。高相似度的无关片段不会作为来源。
- 回答摘取正文，展开可查看完整引用片段、标题、章节、资料来源和版本。回复直接走 SSE，后续对话不会把历史资料原文再发给决策模型。
- 本轮资料状态与来源快照写入现有 `agent_task.collected_facts`，键为 `knowledgeReplies[turnNo]`。现有 SSE 和任务快照可恢复引用，无新增接口或迁移。历史回复保留当时引用的版本，资料归档后不会参与新回复。
- 当前覆盖到院准备、证件、取号、一般检查前注意事项，以及预约确认、实时号源边界、重复提交和取消改约入口。合成预约规则已更新为实际支持的行为，更具体的检查、用药、医保、费用和医生介绍不在本批回答范围内。

| 结果 | 患者体验 |
| --- | --- |
| `ANSWERED` | 展示资料摘录及可展开来源。 |
| `NO_EVIDENCE` | 表示目前查到的资料无法回答，提示向门诊服务台核实。 |
| `UNAVAILABLE` | 表示医院资料库暂时无法查询，提示稍后再试。 |

## 本地使用

已有开发库需要针对其实际 MySQL 配置重新执行 [导入脚本](../../scripts/import-knowledge.ps1)，再用同一配置和可达 Qdrant 执行 [索引脚本](../../scripts/index-knowledge.ps1)。这样会把调整后的预约说明导入为新版本，并将待处理片段加入索引。在已索引的开发库中，旧规则的章节不会被当作新版规则引用。

以患者登录智能导诊页，试问“去医院就诊要带什么证件？”、“预约挂号有什么规则？”或“就诊可以带宠物进诊室吗？”。可先选一个候选，验证提问后确认单保留。

## 验收记录

2026-11-18 在隔离 MySQL 8.0.34、Chrome 和真实 [Qdrant 1.13.6](https://github.com/qdrant/qdrant/releases/tag/v1.13.6) 进程上验证。本地向量模型为 512 维 BGE。导入 6 篇资料，实际索引 29 个片段，失败和待处理均为 0。

| 场景 | 实测结果 |
| --- | --- |
| 查到就诊准备 | “去医院就诊要带什么证件？”引用门诊就诊须知中的证件与凭证。Chrome 展开后可见原文。正常回复、SSE 和刷新后的记录一致。 |
| 查到预约规则 | 一般预约规则返回已发布的合成说明。问取消或改约时，明确提示当前预约记录页没有该入口，并附上对应章节。 |
| 查无资料 | Qdrant 在线时询问宠物能否进入诊室，返回 `NO_EVIDENCE`，引用为空。另有单元用例验证高分无关材料和模型扩大查询范围时不会引用无关内容。 |
| Qdrant 确实停机 | 停止隔离 Qdrant，再在同一待确认任务提问。返回 `UNAVAILABLE`，无新增引用，也未暴露内部连接地址，原方案保持不变。 |
| Qdrant 重启 | 后端保持运行。重启 Qdrant 后，对同一任务再次询问，恢复带引用的回答，原方案仍保持不变。 |

隔离 MySQL 套件 136 项通过，含 53 项集成测试。独立的真实 Qdrant 适配器套件另有 16 项通过，两个套件均无失败、错误和跳过。Vue 类型检查、Vite 生产构建和后端打包通过。浏览器产物和日志保存在本机 `target/s3-rag/`。

患者流程采用本地确定性决策模型。DeepSeek 工具声明和后续轮次的来源隔离有测试替身验证，真实模型调用仍待验收。更广的资料覆盖及完整下架、重建和失败复验仍属于 S3 后续，预约完成后的关联咨询属于 S4。
